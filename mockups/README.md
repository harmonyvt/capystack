# mockups

HTML mockups of every screen, drawn with the real design tokens. They are where UI work starts.

`index.html` is a gallery: the token palette, the component kit (Button, IconButton, Sheet, ListRow, EmptyState,
Skeleton, Toast, SignInCard, TextField) and three screens (sign in, notes, settings), each in a phone frame and a
desktop frame. Open it in a browser; the light and dark buttons flip the theme. It links
`../web/src/lib/design/tokens.css` (generated by `node design/build.mjs`), so a re-skin in `design/tokens.json` shows
up here after a build.

## Workflow (mockup first)

1. Draw the new screen or component in `mockups/` (a new `<name>.html`, or a section in `index.html`). Use only
   `var(--color-*)`, `var(--space-*)`, `var(--radius-*)`, `var(--font-*)`, `var(--motion-*)`. No literal colours or
   pixel sizes that are not tokens. Follow DESIGN.md (lowercase copy, icon-first controls, closes top right,
   skeletons not spinners, no emoji).
2. Show it to the owner: run `node mockups/shoot.mjs` and share the PNGs in `mockups/shots/`, or the HTML itself.
3. Owner says OK. Nothing is built before that.
4. Build it in `web/src/lib/ui/` and `apple/Capystack/Design/` with the same component names.
5. Screenshot the real build next to the mockup and compare (web: Playwright against `npm run dev`; Apple: the
   simulator or `ImageRenderer` previews). Fix the build, not the mockup, unless the owner changes their mind.

## Screenshots

    node mockups/shoot.mjs

Needs Playwright with Chromium (`npm i -g playwright && npx playwright install chromium`; the script finds a global
install). Writes `mockups/shots/gallery-{light,dark}.png` and each screen
(`phone-signin`, `phone-notes`, `phone-settings`, `desk-signin`, `desk-notes`, `desk-settings`) in both themes.
The folder is gitignored; the PNGs are small (about 15 to 40 KB each, the gallery about 350 KB).
